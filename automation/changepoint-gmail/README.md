# 変化点承認依頼メールの設定

送信元は `miyama.firebase@gmail.com`。作成・再編集後は発信部署、対応スタンプ押印後は発生部署のマスターに登録された承認者へ、5分間隔の定期処理で通知します。コードを配置するだけでは送信は始まりません。初回認証と以下の設定が必要です。

生産予定日の入力・変更、および発生部署の最終承認完了は、作成部署（発信部署）の「通知先」へ送ります。この通知先は承認依頼先とは別に設定します。対応者スタンプだけでは作成部署へ通知しません。通知先が未設定の場合、承認者への代替送信はせず保留します。

作成済みのApps Script: [変化点管理 承認依頼メール](https://script.google.com/home/projects/1xhyIESQPR9bA9rbgUjgthWRtTQQwVx5R2bROQa34yU_Jcj3XKh5No9Db/edit)。初回認証と自動送信の開始は未完了です。

## 初回設定

1. 会社で管理する上記Googleアカウントで https://script.google.com/ にログインし、スタンドアロンのApps Scriptプロジェクトを作成します。
2. 同梱の `Code.gs` と `appsscript.json` を設定します。マニフェストはプロジェクトの設定から表示できます。ウェブアプリとして公開する必要はありません。
3. Firebase管理者が、プロジェクト `abnreport-fd733` のGoogle Cloud IAMで送信元アカウントに `Cloud Datastore Viewer` (`roles/datastore.viewer`) を付与します。これはデータベース全体の読み取り権限です。管理者が許可範囲を確認してください。メール処理はFirestoreへの書き込みを行いません。既存のFirestoreルールは変更しません。
4. アプリの「マスター管理 → 部署 → 承認先」で、各部署の承認者名・メールアドレスを登録します。同じ行の「通知先」で、生産日・承認完了の結果を受け取る部署のメールアドレスを登録します。どちらもカンマ区切りで複数登録でき、セミコロン・空白・改行・全角区切りにも対応します。重複は除外します。1設定につき50件、合計6000文字までです。既存の1件設定や部署の配布リストも使用できます。
5. Apps Scriptのスクリプトプロパティに `ALLOWED_RECIPIENTS` を追加し、送信を許可する承認先・通知先の全メールアドレスをカンマ区切りで設定します。部署マスターに登録されていても、この許可リストにないアドレスには送信しません。
6. `previewNotifierConfiguration` を手動実行してGoogleの認証を行い、実行ログで送信元・宛先とFirestore読み取りを確認します。認証エラーが出た場合、アプリの公開ルールを緩めず、IAMとスコープを確認してください。
7. 確認後、`startApprovalNotifications` を一度実行します。以後、パソコンやOutlookを起動しておく必要はありません。
8. 開始後にテストカードを作成して受信確認し、発信部署承認、対応チェック、対応スタンプの順に進め、発生部署承認者にも届くことを確認してください。実際の宛先へ通知されるため、テスト相手に事前連絡してください。

設定前のカードを一斉送信しないため、初回開始日時より前の依頼は対象外です。旧版アプリで作成された依頼にも通知日時がないため、対象外です。全利用者が最新版を再読み込みしてから開始してください。開始時刻はサーバーの実行時刻で記録します。

## 運用

- 承認先の変更時は、部署マスターと `ALLOWED_RECIPIENTS` の両方を更新します。部署名が重複している場合は誤送信を防ぐため保留します。
- 複数宛先は全員をToに指定するため、同じ通知の受信者同士にアドレスが見えます。未許可・不正な宛先が1件でもある場合は全体を保留し、一部の人だけには送りません。
- 送信可能数はメール数ではなく宛先人数で差し引きます。全員分の残数がない場合は全体を保留して、次回以降に再確認します。
- `stopApprovalNotifications` で停止、`startApprovalNotifications` で再開できます。再開は既存の通知記録と取得位置を維持します。
- `showNotificationStatus` で直近の処理時刻・保留理由・通知記録を確認します。成功・対象外の記録は24時間後に削除します。未解決の記録は残します。
- 宛先未設定・読み取り失敗は入力内容を保留し、1時間後以降に再確認します。送信上限に達したものも保留します。
- 送信開始直前に承認状態を再確認し、承認済み・中止・削除・再編集済みの古い依頼は送信しません。ただし再確認直後に状態が変わる場合には通知が届く可能性があります。
- 最終承認完了の結果通知は、完了済みでも送信します。中止・削除・承認やり直しで取り消された結果は送信しません。
- 生産日は直近の更新日時を監視します。定期処理前に複数回変更された場合、途中の古い日付をまとめ、最新の生産予定日を通知します。操作した人・操作日時・カードへのリンクを本文に記載します。
- `sending` または `uncertain` は送信結果不明です。二重送信を避けるため自動再送しません。Gmailの送信済みを確認し、`REVIEW_JOB_KEY` に該当キー、`REVIEW_ACTION` に送信済みなら `sent`、未送信と確認できた場合のみ `retry` を設定して `resolveUncertainNotification` を実行します。再送は重複の可能性を理解して実施してください。
- 記録が200件に達すると新規取得を停止します。保留理由を解消するか結果不明記録を確認してください。開始日時・取得位置・記録を手動削除すると取りこぼしや再送が起こり得ます。
- 専用Googleアカウントの復旧方法と二段階認証を会社で管理してください。パスワードやOAuthトークンをHTML、Git、チャットに保存しないでください。

## 費用と制限

独自ドメインやResend契約は不要です。Apps Scriptの一般向けGmailアカウントは、現在、メール受信者数が延べ100件/日、トリガー合計実行時間が90分/日に制限されています。上限は変更される場合があります。5分間隔は実行時刻・到達時間の保証ではありません。

Firebaseの読み取り回数は別途発生し、既存アプリと同じ利用枠を消費します。通知日時を使って増分だけを取得しますが、マスター取得・保留再確認にも読み取りが発生します。送信先・通信量・運用回数を含む全体の費用が常に無料になる保証はありません。

通知メールは社内の情報をGmail経由で送信します。会社のクラウド利用方針・送信先の受信制限を確認してください。本番で自動送信を開始する前に、専用アカウントでの認証と実配送確認が必要です。
